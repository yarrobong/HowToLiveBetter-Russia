# Полная русификация HowToLiveBetter-Russia — дизайн

**Дата:** 17.09.2026

## Цель

Сделать текущую рабочую версию `HowToLiveBetter-Russia` полностью русскоязычной: убрать китайские имена файлов, китайские служебные теги, китайские инструкции и устаревшие китайские исследовательские заметки из актуального дерева репозитория, сохранив историю форка в Git.

Проект остаётся настоящим fork `eternity4719/HowToLiveBetter`, но пользовательская и рабочая поверхность репозитория становится российской и русскоязычной.

## Что считается завершением

После миграции:

1. В `book/` ровно 31 Markdown-файл, и у всех русские имена.
2. Все 31 ссылки README ведут на новые русские пути.
3. В карточках нет старых китайских hidden-тегов; машинные метаданные полностью русские.
4. `index.html`, checker и тесты понимают только новый русский формат метаданных.
5. `CLAUDE.md` содержит русские правила именно российской редакции.
6. Пользовательские документы в `docs/` имеют русские названия и русское содержание.
7. Старые китайские research-notes, wave-артефакты и неиспользуемые документы удалены из текущего дерева; при необходимости они доступны через историю Git.
8. CI проверяет отсутствие китайских иероглифов в активных текстовых файлах.
9. На финальном `main` unit-тесты и repository checker проходят.

## Допустимые исключения

Не переводятся только технические идентификаторы, где перевод ухудшит совместимость или не имеет смысла:

- название репозитория `HowToLiveBetter-Russia`;
- стандартные имена `README.md`, `LICENSE`, `CLAUDE.md`, `index.html`, `.github`, `.gitignore`, `.nojekyll`, `robots.txt`, `sitemap.xml`;
- имена Python-функций, HTML/JS API и внешние URL;
- оригинальный текст лицензии Unlicense;
- названия сторонних организаций, журналов, стандартов и продуктов, если у них нет официального русского названия.

Китайские иероглифы не допускаются ни в пользовательском тексте, ни в путях файлов, ни в служебной схеме карточек.

## Русский формат машинных метаданных

Старый формат скрытого комментария полностью заменяется русским форматом:

```html
<!-- метаданные: деньги=0 время=мало усилие=нет польза=высокая метрика=деньги -->
```

Допустимые значения:

- `деньги=0|мало|много`
- `время=мало|средне|много`
- `усилие=нет|немного|да`
- `польза=высокая|средняя|низкая`
- `метрика=здоровье|деньги|время|свобода`

`метрика=здоровье` используется для медицинских исходов, включая смертность, заболеваемость, травмы и функциональное здоровье.

Checker больше не должен принимать прежний формат. Наличие старого служебного комментария после миграции считается ошибкой.

## Документация

### Остаётся и русифицируется

- `README.md`
- `CLAUDE.md`
- `docs/СТАТУС-АДАПТАЦИИ.md` → `docs/СТАТУС-АДАПТАЦИИ.md`
- `docs/ИСТОЧНИКИ-РФ.md` → `docs/ИСТОЧНИКИ-РФ.md`
- новая спецификация полной русификации
- новый implementation plan полной русификации

README и `index.html` должны ссылаться только на новые русские пути.

### Удаляется из актуального дерева

Удаляются как исторические артефакты, уже не являющиеся источником истины:

- весь каталог старых китайских проверочных заметок;
- standalone-документы с китайскими именами или китайским содержанием, не используемые российской редакцией;
- старые wave-планы и wave-review файлы, относящиеся к промежуточным стадиям миграции;
- прежняя design-spec адаптации после переноса нужных требований в эту спецификацию;
- старые OG-артефакты, содержащие или потенциально содержащие китайский текст (`og.png`, `tools/og.html`), если они не могут быть гарантированно приведены к русской версии в рамках этой миграции.

История не теряется: удалённые файлы остаются в Git history.

## `CLAUDE.md`

Существующий китайский файл не переводится дословно. Он заменяется коротким русским документом правил текущей российской редакции:

- назначение проекта;
- формат карточки;
- русский формат machine-tag;
- иерархия источников;
- freshness для российских норм;
- запрет на китайские локальные нормы и государственные источники;
- обязательное обновление README/ссылок при переименовании;
- команды локальной проверки и CI.

Это уменьшает технический долг и исключает конфликт между upstream-правилами и российским fork.

## Checker и тесты

`tools/check_russia_adaptation.py` становится проверкой русской редакции и получает новые инварианты:

1. Ровно 31 `book/NN-*.md`.
2. Все 31 имени файлов не содержат китайских иероглифов.
3. README содержит ровно 31 существующую ссылку на эти файлы.
4. Каждая карточка содержит поля `Стоимость`, `Простыми словами`, `Польза`, `Доказательность`, `Источник`.
5. Каждая карточка содержит русский hidden-tag нового формата.
6. Старые китайские hidden-tags запрещены.
7. Российские источники требуют маркер актуальности.
8. Китайские государственные домены запрещены.
9. Активные текстовые файлы репозитория не содержат символов CJK.

Проверка CJK применяется к текстовым расширениям `.md`, `.html`, `.py`, `.yml`, `.yaml`, `.xml`, `.txt`, `.json`, `.css`, `.js`. Из сканирования исключается `LICENSE`, потому что лицензия хранится в оригинальном юридическом тексте, но если в ней нет CJK, это исключение фактически не влияет на результат.

Тесты сначала меняются так, чтобы новый контракт падал на старом дереве (RED), затем выполняется миграция до GREEN.

## `index.html`

Публичный интерфейс сохраняет текущую архитектуру без backend и сборки. Он продолжает читать таблицу разделов из README и Markdown-карточки из `book/`.

Изменения:

- пути автоматически берутся уже из русифицированного README;
- если machine-tags используются в UI, parser переводится на новый русский формат;
- никакого китайского текста, fallback-значений и исторических словарей в JavaScript не остаётся;
- пользовательский интерфейс остаётся полностью русским.

## Порядок миграции

1. Создать RED-тесты нового русского контракта.
2. Переименовать 31 `book/` файлов одним атомарным tree-коммитом.
3. Перевести hidden-tags во всех 31 файлах.
4. Обновить README и все ссылки на документы.
5. Переименовать два основных документа РФ и обновить ссылки.
6. Переписать `CLAUDE.md`.
7. Обновить checker, unit tests и при необходимости `index.html`.
8. Удалить китайские legacy-docs, старые wave-артефакты и stale OG-файлы.
9. Запустить сканирование CJK по всему активному текстовому дереву.
10. Запустить unit tests и repository checker.
11. Открыть PR в `main`, дождаться зелёного PR CI и выполнить squash merge.
12. Проверить CI уже на merge-коммите `main`.

## Совместимость с upstream

После переименования файлов GitHub обычно распознает перемещения по сходству содержимого, однако прямое построчное сравнение с upstream станет менее удобным. Это осознанный компромисс ради полностью русской рабочей структуры.

Связь fork с upstream сохраняется на уровне GitHub. Новые изменения оригинала будут переноситься выборочно, а не через слепой `Sync fork`, потому что российская редакция уже существенно расходится с исходной юрисдикцией и структурой.

## Внешняя метаинформация GitHub

Описание репозитория в блоке GitHub About сейчас унаследовано на китайском. В доступном GitHub connector нет операции изменения repository metadata. Все изменения внутри Git будут выполнены автоматически; About-description остаётся единственным возможным ручным шагом, если API-возможность не появится во время реализации.

Рекомендуемый текст About:

> Доказательный справочник для России: здоровье, безопасность, финансы, право, работа, семья и повседневные решения. 31 раздел, стоимость, польза, доказательность и первоисточники.
